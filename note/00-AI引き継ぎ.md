## 2026-09-22（3） — 立ち絵の左右反転／文字は 3 行の窓で巻き上げる（GS-146）

- **`portrait` に `flip` を足した**（左右反転）。軸は大きさと同じ足元なので、
  裏返しても立ち位置は動かない（CSS の `--flip` を `scaleX()` に掛けるだけ）。
  入り・揺れ・拡大の `transform` 全部に入れてあるので、動いている間も裏返ったまま。
  途中で向きを変えたいときは、**同じ `id` で置き直す**（絵は差し替わるが並びは変わらない）。
- **会話ウィンドウを「3 行の窓」にした**（旧作は 2 行）。`.message-view` が
  35px × 3 行だけ見せ、あふれたぶんは**中身を上へ巻き上げる**（0.2 秒で滑る）。
  ウィンドウの高さ 140px は動かない。4 行目・5 行目を書いても文字が窓の外へこぼれない。
  - 巻き上げる量は**測ってから**（行数では数えない）。長い行は折り返して 1 行が 2 行になる
  - ずらす量は**行の高さの倍数に丸める**。端数で止めると上の行が 4px 切れて見えた

- **次の人の会話は必ず空から始まる。** `setShown(0)` を `useEffect` でやっていたので、
  切り替わった**1 フレームだけ前の文字数ぶん**が出ていた——3 行ぶんが一瞬出てから
  消えて打ち直るので、「決定キーを押した瞬間に文字が勝手に動いた」ように見えていた
  （**利用者の見立てのほうが正しかった**。前回「文字は動いていない」と測ったのは
  同じ文の中だけを見ていたため）。**描く前**（render 中）に巻き戻す形へ直した。
  巻き上げも同時に 0 へ戻す（このときだけ滑らせない——次の 1 行目が下から降りてくるので）。
- 実測: 3 行までは巻き上げ 0、4 行目で −35px、5 行目で −70px。窓は 105px、ウィンドウは 140px。
  次の人に切り替えた 20ms 後の本文は空・巻き上げ 0。

## 2026-09-22（2） — イラストの拡大は効果で（GS-145）／流れる文字の速さを設定に出す

- **絵の大きさを変えるのは効果だけにした。** `.portrait` は丈を `height: 86%` と**決めて**いたので、

- **`imageFx` に `zoom` を足した。** `scale` 倍まで大きさを変える（1 がふつう、2 で 2 倍）。

  アニメ側に書いていない成分は消える）。テストで大きさが残ることを見張っている。
- **流れる文字の速さを設定に出した**（「流れる文字」×0.5〜×4.0）。台帳の `speed` に掛かる。

- 既定の `speed` を **1200 → 1800**（1 行 1.8 秒）に。**1 行が現れる間隔がそのまま読む時間**なので、
  30 字を超える行があるオープニングは 1.2 秒では追えなかった。

  こちらは行が増えると**本当に**上へ伸びる。

## 2026-09-22 — 流れる文字の速さを「1 行ぶんの時間」で決める（GS-144）

## 2026-09-19 — 開発用のつまみを BGM と効果音に分けた（GS-129）

- 設定の「開発用」を 3 つにした（`DEV_MODE` のときだけ出る。覚えは `samplegame.dev`）。

| つまみ | 既定 | 何が止まるか |
| --- | --- | --- |
| オープニングを飛ばす | 入 | オープニング |
| BGM を鳴らさない | 入 | BGM と**環境音**（滝など） |

- **効果音の既定は「鳴らす」。** 文字送りの音は「どこまで進んだか」の手がかりで、
  消すと会話まわりの確認がしづらい。うるさいときだけ切る。
- 止める場所は**入口 1 か所ずつ**（`playBgm` / `playBgs` / `playSe`）。呼ぶ側に条件を撒かない。
  台帳に無い音の警告は**切っていても出す**——名前の書き間違いは切り替えと関係なく知りたい。
- 「鳴らさない」に倒した瞬間に BGM と環境音を止める。効果音は 1 回ずつ鳴る物なので何もしない。
- 確認（`__audio` と `__dev` で実測）: 両方入 → 効果音が鳴り `bgs: waterfall` / `bgm: field`。
  効果音だけ切 → 効果音の再生 0 回。BGM だけ切 → `bgm` も `bgs` も空のまま、効果音は鳴る。

## 2. イベントの形（GS-06 の中身）

### 2.1 なぜ「JSON で関数が動く」のか

**JSON にコードは書かない。書くのは「どの命令を、どんな引数で」だけ。**
実際に動く関数は TS 側の**表**に持ち、実行機がその表を引いて `await` で 1 つずつ動かす。

```ts
// interpreter.ts の中身（要点だけ）
const COMMANDS = {
  message: async (ctx, cmd) => ctx.message(cmd.talk),
  move:    async (ctx, cmd) => { for (const dir of cmd.route) await ctx.step(cmd.target, dir); },
  …
};
for (const cmd of list) await COMMANDS[cmd.type](ctx, cmd);
```

```json
{ "type": "move", "target": "player", "route": ["up", "up", "left"], "speed": 4 }
```

- `await` があるので「**歩き終わってから喋る**」が素直に書ける
- 表に無い命令は**動かない**（`eval` を使わない）。データが勝手なことをできない
- **表がそのままイベントエディタの命令一覧**になる。増やすときは表と型に 1 つずつ足す

### 2.2 今ある命令

`src/event/types.ts` が正。`message` / `choice` / `wait` / `fade` / `move` / `turn` /
`portrait` / `setSwitch` / `setVariable` / `if` / `transfer` / `playSe` / `playBgm` /
`stopBgm` / `callCommon` / `script`。

旧作の 9 本のイベントで使われていた命令を数えて決めた（解析 §5.2）。
**9 本中 7 本はこの表で書ける。** 残り 2 本（オープニングの 40 秒スクロール、戦闘への遷移）は
`script` で逃がす——`script` が書くのは**TS 側に登録した関数の名前**で、コードそのものではない。

### 2.3 確かめたこと

`data/events/home.json`（旧作の家のイベントを写した見本）を実行機に通し、
会話 → 選択肢 → 分岐 → 移動 → 向き → スイッチ → 条件付きのマップ移動が
**書いた順に動く**こと、スイッチが立つまで出口イベントが動かないことを確認した。
※ 素の `tsx` で動かした確認。プロジェクトの土台ができたらテストとして残す。

## 3. セーブの形（GS-04 / GS-05 / GS-27）

**決めて、動いている。** 置き場所は IndexedDB（`samplegame` / `saves`）。
**枠 1〜3 が手で書くぶん、枠 0 がオート**（GS-33）。枠 0 は読むだけで、書くのはゲームの側。

```ts
interface SaveData {
  version: number;        // 形の版。読めない版は触らせない
  savedAt: number;        // 書いた時刻（一覧に出す）
  playSeconds: number;    // 遊んだ秒
  map: string;            // 台帳の番号（"0101"）
  at: { x, y, z };        // マス（整数）
  facing: WalkDir;
  switches:  Record<string, boolean>;   // "home_出発した"
  variables: Record<string, number>;
  self:      Record<string, boolean>;   // "<マップ>/<イベント>/<名前>"
  clear: { count: number; lap: number; carry: Record<string, …> };
}
```

- **初期データとセーブは別物**。初期値は `public/data/`、記録はこの入れ物
- スイッチ・変数は**文字列キー**。番号は破綻する
- **セルフスイッチ**はイベントごとの覚え（「この宝箱は開けた」）。
  宛先はイベントを動かす前に `setScene` で伝える——**条件を見るときにも要る**
- **クリア後・周回**（`clear`）は**まだ使わないが器を置く**。後から足すと互換が切れる
- **設定（`options.ts`）はセーブに入れない**。文字送りや音量は端末の好みで、枠ごとに変わらない

### 4.4 NPC（GS-16）

**マップに人が立ち、正面から話しかけられる。** イベントからも動かせる（`npc:<id>`）。

役割を 3 つに分けてある。

| 何を | どこに | 中身 |
| --- | --- | --- |
| 誰がどこに居るか | マップのオブジェクト | `Npc`（姿のキー）/ `NpcId`（呼び名。省略時は姿のキーと同じ）/ `Event`（話しかけたときのイベント）/ `Face`（初期の向き） |
| どんな姿か | `public/data/actors.json` | シートの絵・横のコマ数・縦の行数・1 コマの大きさ・**行の並び** |
| 何を喋るか | `data/events/<マップ名>.json` | `trigger: "action"` のイベント |

イベントの起動場所も同じ考え方（GS-19）。**`EVENT` という名前のオブジェクトレイヤー**に置いたものは、
`Event` プロパティを書かなくても**オブジェクトの名前がイベント id** になる（`EVENT010101`）。
`default` の点に `Direction` を書くと、出発したときの向きになる。

**NPC になるのは 2 通り**（GS-18）。

1. `Npc` のプロパティが在るオブジェクト（レイヤーはどこでもよい）
2. **`NPC` という名前のオブジェクトレイヤー**に置いた「キャラ画像」（エディタが `Sprite` を書く）

2 は**置くだけで立つ**。姿は `Sprite` のファイル名で `actors.json` を引き当てる
（`chicken_walk.png` → じいちゃんの並び）。台帳に無い絵は横 3 × 縦 4 と見なして出し、
コンソールに書いておく。話しかけたいなら `Event` を、イベントから動かしたいなら `NpcId` を足す。

- **立つのはマスの中央**（GS-18）。エディタで置いた点はマスの縁に寄ることがあり、
  半マスずれて立つと「正面の相手」が斜めになって**話しかけられない**（実測）。
  出発点・マップ移動の着地・NPC はすべて同じ `standOn` を通す
- **作りはプレイヤーと同じ**（`createPlayer` にシートを渡すだけ）。光・影・水面への映り込みも同じ手順で付け、
  毎フレーム同じ `update` を通す。入力の代わりにイベントの歩きを入れるだけなので、
  当たり判定も段差の扱いもプレイヤーと変わらない
- **行の並びはシートごとに違う**。じいちゃんの鶏は上・左・下・右（旧作の `spritesheetKeyOrder` と同じ値）。
  既定は下・左・右・上。横 3 コマなら真ん中が止まり絵、4 コマなら順に回す（旧作の `spriteType` 0304 / 0404）
- **話しかけるのは足元ではなく向いた先**。正面 1.4 マス以内・約 45 度の中で一番近い相手を選ぶ。
  背を向けていれば話しかけられない。NPC の `Event` は床の起動場所には**しない**（踏む必要が出てしまう）
- イベントの `this` は**話しかけた相手**を指す。`npc:<id>` は名前で引く。
  居ない相手を指しても止めず、コンソールに印を出して次の命令へ進む
- **人はすり抜けない**（GS-35）

#### シートの読み方は台帳が決める（GS-47）

```json
"grandpa": {
  "sheet": "assets/spritesheet/chicken_walk.png",
  "cols": 4, "rows": 4, "framePx": [32, 32],
  "order": ["north", "west", "south", "east"],
  "walk":   { "stand": 0, "ms": 160 },
  "wander": { "ms": [2500, 6000], "range": 2 }
},
"chest": {
  "sheet": "assets/spritesheet/chest.png",
  "cols": 2, "rows": 1, "framePx": [32, 32],
  "poses": { "閉じている": 0, "開いた": 1 }
}
```

| 欄 | 意味 |
| --- | --- |
| `order` | 行の並び。省くと 下・左・右・上 |
| `walk` | 止まり絵のコマと 1 コマの秒数。省くと 3 コマなら真ん中・0.16 秒 |
| `footPx` | 足元が 1 コマの下端から何画素上にあるか（GS-52）。**そのぶん絵を下げる**。負で持ち上げる |
| `poses` | 静止コマの名前（GS-47）。`pose` 命令で指す |
| `wander` | うろつき方（GS-48）。`ms` は次に動くまでの抽選幅、`range` は置いた場所からの距離 |

**行は行数で丸める**ので、`rows: 1` の 1 枚絵（宝箱）でもはみ出さない。
向きを持たない物は `order` を書かず `rows: 1` にする。

#### うろつき（GS-48 / GS-50）

**マス単位では歩かない。** 短い距離をゆっくり動いては立ち止まる（旧作と同じ手触り）。

| 欄 | 既定 | 意味 |
| --- | --- | --- |
| `step` | 0.6 | 1 回に動く距離の上限（マス）。毎回 0〜これで抽選。旧作の ±20px 相当 |
| `walkMs` | 1000 | その距離を歩くのにかける時間。**速さはここから出す** |
| `ms` | [1700, 3300] | 立ち止まっている時間 |
| `range` | 2 | 置いた場所から離れてよい距離（マス） |

- 台帳の `wander` が**キャラの性質**。マップのプロパティ `Wander` が**個体を上書き**する
  （`Wander = 2` で 2 マス以内、`Wander = 0` でこの個体だけ止まる）
- **プレイヤーが 1.25 マス以内に来たら止まる**（歩いている途中でも）。旧作の 40px と同じ
- 会話中も止まる。並行イベントの裏では止まらない
- イベントの `move` は今までどおりマス単位・歩きの速さ（うろつきだけが遅い）

`action` のイベントを持ち、**いま条件を満たしている** NPC の頭の上に `bubble.png` を出す。

### 4.5 マップ移動（GS-17）

**マップに置いた `MapMove` のオブジェクトだけで、行き先も立ち位置も向きも決まる。**

| 書くもの | 例 | 意味 |
| --- | --- | --- |
| `MapMove` | `0102` | 行き先のマップ。**番号**（台帳を引く）でも**ファイル名**でも |
| `MoveTo` | `入口` または `5,0,2` | 着いたときの立ち位置。**名前 1 つ**なら行き先マップのその点オブジェクト、**数 3 つ**ならそのマス（x,y,z）の**中央**。空なら行き先の `default` |
| `Direction` | `Down` | 着いたときの向き。`Up` / `Down` / `Left` / `Right`（`north` … でも可）。空なら向きはそのまま |

- **座標はマスの番号（整数）**。書いたマスの**中央**に立ち、高さはそのマスの床に乗る（GS-17）。
  小数は書かない——書けるようにすると、書く側が半端な位置を気にすることになる。
  高さ（y）も要る——森は床が y=10 なので、`x,0,z` と書くと地面の下を指す
- **名前で書くほうを勧める。** 座標はマップを描き直すとずれるが、点オブジェクトなら一緒に動く
- 行き先の番号 → ファイル名は `public/data/maps.json`。マップを増やしたらここへ 1 行足す。
  台帳に無ければ書いた名前をそのままファイル名として試す
- 台帳の 1 行が持つのは**ファイル名・曲（`bgm`）・環境音（`bgs`）・戦闘の背景（`battleField`）**。
  `battleField` は `battlefields.json` のキーで、書かなければ戦闘の下地は**そのマップの 3D**（GS-79）
- **体が触れたら動く**。入口の枠は壁と同じ位置に描いてよい（エディタのヘルプもそう書いてある）。
  中心点だけで見ていたときは、壁に当たって止まった位置から**0.01〜0.08 マス届かず**踏めなかった。
  体の太さ＋指 1 本ぶんの余裕で見る
- イベントの `transfer` も同じ道を通る（`GameCanvas.goTo`）。`face` を書けば着いた向きも決まる

確認: 家の戸口へ歩くと森へ出て**南を向いて**立つ。森から家の入口へ歩くと家に戻り**北を向く**。
`MoveTo` に `入口`（点の名前）と `4,0,1`（マス）を入れて、名前はその点に、マスは**その中央**（4.5, 1.5）に立つことを確かめた。

### 4.6 立ち絵とフォント（GS-20）

**`portrait` で立ち絵を出す。** 画面の下端に足を付けて立ち、会話ウィンドウがその前に重なる。

```json
{ "type": "portrait", "slot": "left", "who": "meina", "face": "normal" }
{ "type": "portrait", "slot": "left", "hide": true }
```

- `slot` は置き場所（`left` / `right` / `center`）。同じ場所は 1 枚だけで、置き直すと差し替わる
- `face` は `characterdata.json` のキー（`normal` / `smile` / `unger`）。
  **空欄は「その表情は無い」**ので `normal` に落とす——絵が消えるより分かりやすい
- 絵は `assets/img/CharaStand/<名前>.png`。旧作からそのまま写した（20 枚）
- **イベントが終わったら片付ける**。出しっぱなしで歩き出すと、消す手立てが無い
- 出入りは**来た側から／来た側へ**（GS-31）。左の絵は左から出て左へ帰る。0.28 秒
  （実測: 右の絵は left=1460 から 937 へ入り、消すときは 937 → 1332 と画面（1280）の外へ出てから消えた）
- 入りは `animation`、出は `transition`。**入りは差し込んだ瞬間に 1 回だけ**動かせばよく、
  出は「印が付いてから」動かすので、CSS の仕掛けが別になる
- **出ていく印を付けるとき、並びを変えない**（GS-31 の落とし穴）。印を付けるだけなのに
  `[...rest, going]` と末尾へ積み直すと、React が `<img>` を DOM 上で並べ替え、
  **移された絵は入りの `animation` がもう一度走る**——消すつもりが画面の外から現れ直す。
  念のため `.portrait.leaving { animation: none; }` も置いて、走り直しても入りが効かないようにした
  （実測: EVENT010201 の「左を消す → 右を消す」で出た。直したあとは
  左が 0 → −608、右が 0 → +523 と**その場から外へ**動いて消える）
- `instant` を立てると**どちらも動かない**。暗転の裏で並べておく場面用
  （`{ "type": "portrait", "slot": "left", "who": "grandpa", "instant": true }`）
- 暗転（`fade`）より下に敷いてあるので、暗転すると一緒に消える

**文字は旧作と同じ PixelMplus10。** `assets/fonts/` に置いて `@font-face` で読む。
10px の絵なので **20px（2 倍）** で出す。会話・名前・選択肢はすべて 20px に揃えた。
使ってよいかは `assets/fonts/README.txt`（M+ FONT LICENSE）。

確認: 家に入るとすぐ `EVENT010101`（オープニング）が動き、**メイナの立ち絵が左に出て**
3 つのメッセージが流れ、終わりに立ち絵が消えてスイッチが立つ。2 回目は動かない。

### 4.7 音（GS-21）

**BGM・環境音・効果音の 3 系統。** 台帳は `public/data/sounds.json`。

```json
{ "sounds": { "field": { "file": "おとぼけダンス(Silly_dance).mp3", "volume": 0.5, "loop": true } },
  "ui": { "message": "message", "decide": "decide", "cancel": "cancel" } }
```

- **増やし方**: `public/assets/sound/` へファイルを置き、台帳に 1 行足すだけ。
  イベントからは `{ "type": "playSe", "key": "決めた名前" }`
- **マップの曲と環境音**は `public/data/maps.json`（`bgm` / `bgs`）。
  マップを移っても**同じ曲なら切れない**——0101 と 0102 は同じ `field` なので繋がったまま鳴る
- **環境音は曲と別系統**。森の滝（`waterfall`）は曲を変えても流れ続ける
- `ui` は画面が自分で鳴らす音。会話が出たとき・選んだとき。差し替えにコードは触らない
- **文字送りの音は 1 文字ごと**（GS-24）。器は音ごとに 6 本を使い回す（実測: 37 文字で 37 回鳴って、器は 6 個）

**設定は `src/game/options.ts`（GS-25）。** 画面はタイトルと Esc メニューの「設定」から（§4.14）。

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| `charMs` | 40 | 文字送り（1 文字あたりのミリ秒）。**大きいほど遅い** |
| `masterVolume` / `bgmVolume` / `seVolume` | 1 | 音量（0〜1） |

`setOptions({ charMs: 60 })` で変える。**その場で効く**——音量は鳴っている曲にも、文字送りは次の 1 文字から。
開発中は `window.__options` から試せる（実測: 200 にすると 1 秒で 5 文字）。
ほかに `window.__game`（マップと人）・`__event`（動いているイベント）・`__audio`・`__ui`（`busy` や `phase`）。
**見えないものは直せない**——「歩けないのはイベントの最中だからか、別の理由か」がこれで分かる。
なお入力は `event.code` を見ている（`ArrowLeft` / `KeyA`）。作った鍵イベントで試すときは `code` を入れる。
- **ブラウザは操作があるまで音を出さない。** 最初のキー／クリックで鳴らし始める（`unlockAudio`）

### 4.8 会話の見せ方（GS-23）

**2 通りある。** どちらも同じ `message` 命令で、`style` が違うだけ。

| | 見た目 | 使いどころ |
| --- | --- | --- |
| `window`（既定） | 下の会話ウィンドウ＋立ち絵 | イベント（オープニング、見送り） |
| `bubble` | 頭の上の吹き出し＋顔アイコン | フィールドの立ち話（NPC に話しかける） |

- 吹き出しの位置は**3D に聞く**（`GameView.headAt`）。カメラが動いても 0.1 秒ごとに追う
- **頭から 22px 浮かせる**。頭のすぐ上に置くと箱がキャラの顔まで覆う。
  空いた分は角（しっぽ）を伸ばして埋め、誰が喋っているかは変わらないようにした
- 主人公が喋っていればプレイヤーの頭、それ以外は**話しかけた相手**の頭。
  相手が分からない場面（`this` が無い）はウィンドウへ落とす——宙に浮いた吹き出しにならないように
- アイコンは `characterdata.json` の `icon`。猫のように持っていないキャラは絵なしで出る
- 位置を測るのは **`useLayoutEffect`**（描く前）。`useEffect` だと 1 フレームだけ位置が無いまま描かれ、
  逃げ場の「画面の真ん中」に**最初の吹き出しだけ**出てから飛んで見える。
  **画面に重ねて 3D の座標へ置くものは、測ってから描く**——話せる合図（GS-49）も同じ話
- **立ち絵は会話用の絵が既定**（`talk` → `normal`）。メイナはバストアップ（`EventTalkImage001`）が出る

**流れる文字**（`scroll`）はオープニング用。画面を半分暗くして下から上へ流し、決定キーで飛ばせる。
速さは**1 行ぶんの時間**（`speed`。既定 1200ms）で決める——総時間で決めると行数の少ない読み物ほど
速く流れて読めない（GS-144）。

出入りは 4 段（**黒で覆う → 明ける → 流す → 薄れる**）。

- **暗幕を張る所は見せない。** 出た瞬間は画面を**真っ黒**にし、その裏で暗幕と文字を置く
- その前の**マップの読み込みも黒いまま**（GS-28）。黒は一瞬で覆い、
  踏んでいる場所のイベントを黒いうちに起こしてから明ける。素の画面は 1 フレームも出ない
- 1 フレーム置いてから黒を 0.6 秒で明ける。現れるのは**暗幕が最初からかかった画面**
- 文字が流れ出すのも明けてから（黒のあいだは止めておく）
- 終わりは暗幕ごと 0.8 秒かけて薄れ、いつもの画面に戻ってから次の命令へ——旧作と同じ間

確認: 家に入るとまず**文字が流れ**（16 行・40 秒・背景 50% 暗）、決定キーで飛ばすと
メイナのバストアップ＋「ごちそうさまでした。」。鶏に話しかけると**頭の上に吹き出し**が出て、
メイナの番はプレイヤーの頭（アイコン `Icon_20250609`）、じいちゃんの番は鶏の頭（`Icon_20240622_鶏`）に移る。
森の猫は 2 匹ともアイコン無しの吹き出しで喋る。

### 4.11 タイトルとセーブ（GS-27）

**タイトル → はじめから／つづきから → 遊ぶ → Esc でセーブ**、が通る。

| 画面 | 中身 |
| --- | --- |
| オープニング（GS-126） | 2 人の立ち絵と家の絵が左右から入ってすれ違い、端へ抜ける（`data/opening.json`）。押すと飛ばせる |
| タイトル | 題名（抜けたあとの家の絵が背になる）、「はじめから」「つづきから」「設定」 |
| メニュー（Esc） | 左に主人公、タブは**アイテム / セーブ / 設定**、下に「タイトルへ」「とじる」（§4.16） |
| セーブ（メニューのタブ） | **オート**＋枠 3 つに**書く／読む**（オートは読むだけ） |

- メニューはキーを capture 段階で止める。開いている間は歩けない（会話ウィンドウと同じ）
- **記録の入れ物は差し替えず中身を移す**。イベントの道具立てが同じ入れ物を握っているため
- 遊んだ秒はタイトルに居る間は数えない

  タイトルの曲（`opening`）はそのつど鳴る。開発モードでは既定でどちらも切ってある
- **オートセーブは入口をくぐって着いた所で**（GS-33）。イベントの `transfer` では書かない
  ——話の途中で場所だけ移る移動があり、そこで書くと読み戻したとき話が半分から始まる
  （実測: 手をふさいだまま 4 秒待つと枠 0 は前のまま、空いた 0.1 秒後に新しい場所が入った）

確認: はじめから → オープニング → 枠 1 に書く（`{version:1, map:"0101", at:{0,0,-3}, facing:"left",
switches:{"EVENT010101":true}, clear:{count:0,lap:1}, playSeconds:24}`）→ 森へ移動 → 読む → 家の同じ場所へ戻る →
タイトルへ → つづきから → 同じ場所から再開。スイッチが戻るのでオープニングは二度と流れない。
セルフスイッチはイベントごとに独立していることも確かめた（`ev_test/A` は true、`ev_other/A` は false）。

### 4.12 歩きの当たり（GS-116。もとは GS-29）

**当たりはマスの四角。1 マス幅の戸口へは、真っ直ぐ歩くだけで入れる。**

- 体は**マス 1 つぶんの四角**。丸ごと塞がるマス（ブロック・斜面・`NoEntry`・人）に当てる。
  **薄い壁チップの帯は細い体（八角形 0.28）で見る**——薄い壁は歩けるマスの中に描いてあるため
- 進めなかったフレームだけ、**体が半分以上かかっているマスの真ん中**へ、進みたい向きと
  直角に歩いて揃える（`player.ts` の `laneSlip`）。揃えば前へ進めるときだけ寄せる。
  寄せているあいだは**寄る方へ体を向ける**
- 斜めへ逃がす `deflect`（DEC-243）とは別物。あちらは**前へ進みながら**横へ逃がす
- **行き止まりでは動かない**。揃えても前へ進めないなら何もしない
- 止まるときは**壁の手前まで詰める**（`creep`）。1 フレームぶん進めないと止まる作りなので、
  これが無いと壁との間に隙間が残る

確認: 1 マス幅の通路（0101 の x=-8 の列）へ、中心から 0.18 マスずれた位置で北を押し続けると、
x が -7.32 → **-7.46** → -7.500 ちょうどと自分で寄ってから通路へ入った（斜め入力なし）。
行き止まりの壁に押し当てても横へは動かない。

**この変更はゲーム側だけ**（`SampleGame/src/game/player.ts`）。ゲームビュー（5926）の写しは触っていない。

#### 同じマスに床を重ねたときの高さ（エディタ側 DEC-386）

**平らな地面の上に丘レイヤーを重ねてよい。** 同じマス・同じ高さに床チップが 2 枚以上あったら、当たりも影も**4 隅ごとに高いほう**を採る。

以前は採り方が逆で（当たり＝後のレイヤー／影＝先のレイヤー）、坂を歩くと**影だけ半マス潜って**いた。

- 実測: 0103 の (10,0,27) で 影 0.00 / 当たり 0.50 → いまはどちらも 0.50
- 0102 が無事だったのは、坂を地面レイヤーの中に直接置いていて 1 マスに床が 1 枚しか無いため
- **飾りレイヤーで坂を潰す事故もこれで防げる**（`Walkable = false` を付け忘れても、坂のほうが高いので残る）

#### 入口の四角は「立てる場所」に掛けて置く（GS-17 の落とし穴）

**壁の面はマスの境目ではない。** HD-2D の壁は 1 マスより薄いので、壁ぎわで
プレイヤーが近づける限界は、マスの線より**手前で止まる**。踏む判定（`MapMove` / `touch`）の
四角がその線の向こうにあると、見た目は入口の上でも**一生踏めない**。

実測（0101 の玄関、体の太さ 0.28 ＋ 触れた余裕 0.1）:

| | |
| --- | --- |
| 家の側から近づける中心 | z = **3.514** まで（壁の面が 3.794。マスの境目 4.0 ではない） |
| 触れられる先 | z = **3.894** まで |
| 四角 `z 4〜5` | **届かない**（0.106 足りない）。ポーチ側は幅 0.23 マスの袋小路で、歩いても入れない |
| 四角 `z 3.55〜5` | 届く（余裕 0.34）。**壁の面より手前へ食い込ませる**のが要点 |

道の途中に置く入口（0102 の森側、`x 6〜7 / z −3〜−2`）は**1 マスちょうどでよい**
——そのマスの上を歩けるので、手前のマスに立った時点で縁に触れる（実測 z=−1.708 で発動）。

確認: 家 → 森 → 家 → 入り直して → 森、が歩くだけで通る。着地（`MoveTo=5,0,3`）は
入口の四角に触れる位置だが、**いったん出るまで次を受け付けない**ので跳ね返らない（DEC-247）。

### 4.13 イベントエディタ（GS-30）

```
MapEditor3D/Event Editor/start.bat   →  http://localhost:5927
（中身は node server.mjs [ゲームのフォルダ] [--open]。省くと隣の SampleGame）
```

**`public/data/events/<マップ>.json` を読み書きする道具。** 旧作はイベント 1 本が TS のクラスで、

打っている間はまとめて 1 段になり、マップを開き直すと覚えは捨てる。

| できること | |
| --- | --- |
| マップを選ぶ | 台帳（`maps.json`）から。イベントが無いマップは「新規」と出る |
| イベント | 追加・複製・削除・並べ替え。id / 起動（action・touch・auto）/ 話し相手 / 条件 |
| 命令 | 追加・削除・並べ替え。**入れ子**（選択肢の枝、条件の中）もそのまま編集できる |
| 欄 | 種類ごとに形が変わる。キャラ・音・マップ・NPC・向きは**一覧から選ぶ**（綴り違いが起きない） |
| 保存 | Ctrl+S。新しく作ったら `files.json` も作り直す |

- NPC の一覧は**マップから読む**（`Npc` のプロパティ、または `NPC` レイヤーのキャラ画像）
- 空の欄は書き出す前に落とす。`null`・`false`・`0` は意味があるので残す

確認: 0101 を開いて命令の中身が出ること、選択肢の枝（「0: はい」の下の命令）が編集できること、
0103（イベント無し）で新規に作って保存すると台帳も更新されること、
**往復しても中身が変わらない**こと（保存し直して `diff` が中身ゼロ。書式は 116 行 → 61 行に締まった）。

### 4.14 設定画面（GS-32）

**タイトルからも、遊んでいる最中（Esc → 設定）からも同じ画面**（`src/ui/SettingsMenu.tsx`）。

> 後から載せた画面の `stopPropagation` では下の画面を止められない
> （実測: 直す前は Esc 1 回で 2 枚とも閉じた）。重ねる画面を作るときはここに戻ること。

式は旧作のまま:

```
ダメージ = max(攻撃力 + 技の効き目 - (守り + このターンの防御), 1)
```

- **必ず 1 は通す。** 0 だと「効いていない」のか「当たっていない」のかが見ている側に分からない
- **回避中だけは 0。** 当たっていないので、最低 1 の決まりの外に置く

- 満タンの HP・攻撃力は**台帳だけ**が持ち、いま減っているぶんが**セーブ**（`items` と同じ分け方）

#### 画面と流れ

| | |
| --- | --- |
| `src/game/battle/flow.ts` | 1 戦を頭から終わりまで。**`await` で 1 手ずつ**（イベントの実行機と同じ作り） |
| `src/ui/battle/BattleView.tsx` | 見せる・選ばせる。面子は `useRef`、動いたことは `tick` で知らせる |
| `battle` 命令（note/01） | イベントから戦う。`win` / `lose` / `escape` の枝 |

- 手は**先に全員ぶん選ばせてから**動かす。選んでいる途中に敵が動くと「殴ろうとした相手がもう居ない」が毎回起きる
- 選んだ相手が先に倒れていたら、**生きている別の相手へ回す**（空振りで 1 手損させない）
- **守りは速さより先**。順番どおりだと足の遅い者の防御は殴られた後に効く
- 逃げは速さの差で 0.25〜0.9。**必ず 1 割は失敗する**——確実な逃げは緊張が消える
- 負けは `lose` の枝が無ければゲームオーバー。`GameOver` を投げてイベントを止める（**エラーではなく合図**）
- 戦いの曲は `battle`（GS-62）。戦闘中は環境音を止め、終わったらマップの台帳から鳴らし直す
- 画面の並びは**旧作に合わせた**（GS-77 / GS-79）：命令が左（x=250 / y=520）、その右に隊列（x=420。**横並びで 3 人ぶんを等分**）。
  2 つは**座標で置く**（横に並べない）——命令の窓は中身に合わせて広がるので、並べると顔と帯が右へずれる。
  **出来事の文は命令の窓と同じ場所に重ね**、一定時間で消える（画面の最下段には窓を置かない）。
  選んでいる行は**▶ と明るさ**で示す（番号で持つので、押せない行があっても居場所が分かる）。
  **敵の居場所は高さを決め打つ**（490px）——文が伸びても一覧が伸びても敵は動かない

#### レベル上げ（GS-63）

```
つぎのレベルに要る経験 = base × レベル ^ rate    （base 8 / rate 1.7）
   L2=8  L3=34  L4=86  L5=170  L6=293
そのレベルの数値 = レベル 1 の値 + 伸び × (レベル - 1)
   メイナ L3 → HP 62（50+6×2）・MP 26・攻撃 36
```

- 経験は**倒れた人にも**配る。上がったら**満タンまで戻す**
- 覚える技は `learn`（レベル → 技の id）。**同じ技は 2 度覚えない**
- **負けても話が続く戦いの後は HP 1 で起こす**（`revive`）。倒れたまま歩くと出会い頭で必ず負ける
- 取り分（経験・お金）を入れるのは戦闘画面。メニューの左の柱に「つぎまで」を出す

### 4.18 ゲームパッド（GS-58）

**繋ぐだけで効く。** 設定も切り替えも要らない（`navigator.getGamepads()` を毎フレーム見るだけ）。

| ボタン | |
| --- | --- |
| ○（1） | 決定（Enter） |
| ✕（0） | キャンセル・とじる（Esc） |
| △（3） | メニュー（Esc） |
| 十字（12〜15）・左スティック | 歩く・一覧の上下左右（傾き 0.35 から） |
| L・R（4〜7） | 走る（Shift） |

`src/game/gamepad.ts` が押した／離したを**合成のキーイベント**にして `window` へ流すだけで、既存の入力（`input.ts` / 会話ウィンドウ / メニュー / Esc）はそのまま動く。

**これで穴が 1 つ見えた。** メニュー中に歩けてしまうのは、止め方が「メニューがキーを飲み込むから」だったため——合成イベントは `window` へ直に送るので捕まえる段が無い。止める理由は `canWalk()` に集めた（GS-59）。

- **合成イベントはボタンを押さない。** 焦点のあるボタンは Enter で反応しないので、タイトルとメニューで自分で `click()` している
- タイトルにキー操作を足した（↑↓ で選ぶ／Enter で決定／Esc で記録一覧を閉じる）。**キーボードでもタイトルが操作できていなかった**ので、その穴も一緒に塞がった
- 押しっぱなしの連射は 400ms → 120ms。`repeat` を立てるので歩きには効かない

確認: 偽のパッドを差して、○ で設定を開く → ✕ で閉じる → ○ で「はじめから」→ スティックで歩く → △ でメニュー → 十字でタブと項目 → ○ で決定 → ✕ で閉じる、まで通した。

### 5.4 細かい穴

- **状態異常はまだ 2 つ**（どく・ねむり。GS-69 / GS-71）。麻痺・沈黙・混乱のような
  「できることが減る」型を足すなら、`data/ailments.json` に 1 行足すだけでは済まない——
  **どの手を選ばせないか**を画面（`BattleView` の一覧）と流れ（`flow.ts`）の両方が知る必要がある。
  いまの `skip`（行動できない）は全部を止めるだけで、「魔法だけ使えない」は表せない
- **攻撃の絵をどう増やすか、まだ決めていない**（GS-83。あとで検討する）。いまは `effects.json` に
  1 行足して技の `effect` で指すだけで出る（コマを並べた 1 枚絵をめくり、大きさを伸ばす形だけ）。
  旧作は技ごとにクラス（`MagicFrame` / `WindCutter`）を書いていた。決めること:
  ①台帳の記述だけで足りる形に留めるか（動きの種類を `scale` / `yoyo` のような欄で増やしていく）、
  ②動きごとに TS の部品を登録する形にするか（台帳は部品の名前と値を持つ。イベントの命令表と同じ作り）、
  ③エディタで作って確かめる道具を持つか（カメラ編集の「カメラ演出」のように試せる場所）
- **イベントに足りない命令が 3 つ見えている**（GS-127）。①**1 枚絵を見せる**（旧作 `EVENT020301` の 3 枚の絵本、
  `EVENT010401` の一枚絵）、②**タイトルへ戻る**（エンディングの締め）、③**イベントの中で移ったマップの `auto` を動かす**
  （いまは `play()` が `busy` で弾くので、`transfer` の先のイベントが始まらない）
- **0103 / 0105 / 0201 のマップにイベントの起動場所がまだ 1 つも無い**（GS-127）。いまは `auto`（入ったら動く）で
  代えている。マップエディタで `EVENT` レイヤーに枠を置けば `trigger` を `touch` に変えるだけで移せる
- **旧作のタイトルにあった「おまけ」「あそびかた」がまだ無い**（GS-126）。オープニング・題名・
  はじめから／つづきから／設定までは揃っている。おまけはクリア後に出る作りだった（`Omake` / `Manual`）
- **表情差分**（`smile` / `unger`）を使ったイベントがまだ無い
- **`app/globals.css` は 1 枚なので、クラス名の取り合いに気づけない。** `.battle-back` を
  「Esc でもどる」の札に使っていたところへ、背景の層として**同じ名前**を足してしまった——
  型検査も画面の警告も出ないまま、背景が `opacity: 0.6` で暗くなり、札は `inset: 0` で
  画面いっぱいに伸びていた（`.battle-stage` に直した）。**新しいクラスを足す前に grep する**
- 出来事の窓は**下の段ぜんぶ（命令＋隊列）を覆う**。旧作も同じ置き方で、覆っていいと決めた
  （GS-79）——ただし**文が出ているあいだは HP の帯が見えない**。見せたいなら文の窓を
  隊列の窓の左端までに縮めるか、隊列の窓を下へずらすことになる
- ~~**入力**はキーボードだけ~~ → **ゲームパッドが効く**（GS-58。§4.18）。残るは仮想パッド（触る画面）だけ
- PWA / Electron（GS-08。土台ができたので、必要になったときに足す）
