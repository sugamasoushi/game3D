# イベントの書き方

**これはイベントエディタの仕様書でもある。** ここに書いてあることが、エディタで
選べるもののすべて。人が手で書いても、エディタが吐いても、同じ JSON。

エディタは `MapEditor3D/Event Editor/start.bat`（→ http://localhost:5927）。命令の表は
`Event Editor/index.html` の `COMMANDS` にあり、**この文書と `src/event/types.ts` が正**。
命令を足すときは 3 つとも直す。**直し忘れは `node check.mjs` が見つける**（GS-42）。

- 置き場所: `public/data/events/<マップのファイル名から .json を取ったもの>.json`
  （例 `public/mapdata/0101_home.json` → `public/data/events/0101_home.json`）
- 文字は UTF-8。フラグや変数の名前に**日本語を使ってよい**（変数の `所持金` など）
- **JSON にコードは書けない。** 書けるのは命令の名前と引数だけ（GS-06）

---

## 1. ファイルの形

```json
{
  "map": "0101_home",
  "events": [ { "id": "…", "trigger": "…", "commands": [ … ] } ]
}
```

### イベント 1 本

| 欄 | 要る | 中身 |
| --- | --- | --- |
| `id` | ○ | 名前。マップのオブジェクトから指すときの合図になる |
| `trigger` | ○ | `action`（決定キー）/ `touch`（踏む）/ `auto`（マップに入ったら）/ `parallel`（裏で動く） |
| `when` | | 動く条件。`[{ "switch": "名前", "is": true }]`＝**そのフラグがまだ動けるとき**（GS-147）。セルフフラグなら `[{ "self": "A", "is": false }]`。`is` を省くと `true`。**全部**満たしたときだけ動く |
| `npc` | | 話しかける相手（NPC の名前）。これを書くと、その NPC に話しかけたときに動く |
| `commands` | ○ | 命令の並び。上から順に、1 つ終わってから次へ |

### 裏で動く（`trigger: "parallel"`。GS-43）

**プレイヤーを止めずに、世界のほうを動かす**ための起動。ほかの 3 つと並べると役割がはっきりする。

| trigger | いつ動くか | プレイヤー | 置き場所（マップのオブジェクト） |
| --- | --- | --- | --- |
| `action` | 決定キーを押したとき | **止まる** | 要る |
| `touch` | そのマスを踏んだとき | **止まる** | 要る |
| `auto` | マップに入ったとき | **止まる** | 要らない |
| **`parallel`** | **条件が満たされたとき** | **止まらない** | 要らない |

#### 決まり

- 条件（`when`）が満たされた**その 1 回**だけ動く。**回り続けない**
- 条件が**崩れて、また満たされた**ら、もう一度動く
- `when` を書かなければ「常に真」なので、**マップに入った時点で 1 回**動く
- 見ているのは 0.1 秒ごと（踏むイベントと同じ見張り）
- 持ち場は**フラグ・変数・音・NPC の歩き・`script`**
- **会話・選択肢・流れる文字は動かない**（`if` の枝の中でも落ちる）。返事を待つ命令は、
  歩いている最中に割り込むとプレイヤーの操作と取り合いになる。話は `action` や `auto` の仕事。
  落とした命令はブラウザのコンソールに 1 度出る

#### 使いどころ

**1. 話が進んだら、別の場所の世界が変わる**（いちばんの用途）

```json
{ "id": "鶏が見送りに出る", "trigger": "parallel",
  "when": [{ "switch": "EVENT010201" }],
  "commands": [
    { "type": "move", "target": "npc:chicken_walk", "route": ["down", "down", "right"] }
  ] }
```

森で見送られたあと家に戻ると、鶏が動いている。`action` / `touch` は「話しかける・踏む」が要り、
`auto` は入った瞬間に画面が止まる。**歩いている裏で勝手に動く**のは `parallel` だけ。

**2. マップに入った瞬間の演出を、止めずに出す**

```json
{ "id": "館の空気", "trigger": "parallel",
  "commands": [
    { "type": "stopBgm", "fade": 600 },
    { "type": "playSe", "key": "cancel", "volume": 0.4 }
  ] }
```

ふつうの BGM・環境音は `maps.json` に書くほうがよい（仕組みが既にある）。これは**演出**向け。

**3. 条件が揃った瞬間に合図を出す**

```json
{ "id": "次が開いた合図", "trigger": "parallel",
  "when": [{ "switch": "EVENT010101" }, { "switch": "EVENT010201" }],
  "commands": [
    { "type": "playSe", "key": "chest" },
    { "type": "setSwitch", "key": "第2章", "value": true }
  ] }
```

「複数の条件が揃った瞬間」は、ほかの trigger では**置き場所をどこにするか**で困る。

**4. 数を数える**

```json
{ "id": "森に来た回数", "trigger": "parallel",
  "commands": [{ "type": "setVariable", "key": "森_来訪", "value": 1, "op": "add" }] }
```

#### 落とし穴: 出入りのたびに動く

**マップを移ると覚えを捨てる**ので、条件が真のままなら**入り直すたびにもう一度動く**。
上の 1 番なら、家に入り直すたびに鶏がまた歩く。

本当に 1 回きりにしたいときは、**イベント自身に印を付けて条件に混ぜる**。

```json
"when": [{ "switch": "EVENT010201", "is": true }, { "self": "A", "is": false }],
"commands": [ … , { "type": "setSelfSwitch", "key": "A", "value": true } ]
```

セルフフラグはセーブに入るので、これで本当に 1 回きりになる。

#### 使わないほうがよい場面

| やりたいこと | 正しい道具 |
| --- | --- |
| マップの BGM・環境音 | `maps.json` |
| 話しかけたら喋る | `action` |
| 踏んだら始まる | `touch` |
| 入った瞬間に**話が始まる** | `auto`（止めてよい場面） |

#### できないこと

**毎フレーム見張る用途には使えない。** 1 回動いたら、条件が崩れるまで動かない。

- NPC をうろうろ歩かせ続ける
- 敵に近づいたら戦闘（距離を毎フレーム見る必要がある）
- 時間で何かが変わる

ツクールの並行処理は**ループ前提**（毎フレーム回る）だが、こちらは回さない——
回すと、書いた人の意図と関係なく音が鳴りっぱなしになったり変数が際限なく増えたりする。
見張りが要る使い方が出てきたら、そのとき別の仕掛けを足す。

**どこで起きるか**はマップが決める（GS-14）。

- オブジェクトのプロパティ `Event` にイベントの `id` を書く
- `EVENT` という名前のオブジェクトレイヤーなら、**オブジェクトの名前がそのまま `id`**（GS-19）
- `CLICKEVENT` という名前のオブジェクトレイヤーなら**調べ物**（GS-55。下）
- NPC に話しかけさせたいだけなら、イベント側に `npc` を書けばマップは触らなくてよい（GS-22）

### 調べ物（`CLICKEVENT` レイヤー。GS-55）

本棚やタンスのように、**そこには立てないが調べられる**物。旧作の `CLICKEVENT` と同じ。

- `CLICKEVENT` レイヤーに四角を置き、**名前をイベントの `id`** にする（`EVENT` と同じ）
- イベント側は `trigger: "action"`
- **踏んでも起きない。** 隣に立って**その方を向いて**決定キー——横に並んだだけでは起きない
- 届くのは**体の中心から 1.25 マス**。目の前のマス 1 つぶん

```json
{ "id": "click0001", "trigger": "action",
  "commands": [
    { "type": "message", "style": "bubble",
      "talk": [{ "who": "meina", "lines": ["新しく覚える魔法は何が良いかな？"] }] }
  ] }
```

**四角は目の前のマスに掛かるように置く。** 壁にぴたりと寄せて細く描くと、
プレイヤーが立てる場所から遠くなって届かないことがある——マス 1 つを覆うのが安全。

> `who` を `meina`（主人公）にすると吹き出しは**プレイヤーの頭の上**に出る。
> ほかの名前にすると、**調べた物の上**に出る（GS-55）——立て札のような物に使える。

## 2. 命令

### message —— 会話

```json
{ "type": "message", "talk": [
  { "who": "meina", "lines": ["今日は何食べようかな～♪"] },
  { "lines": ["（名前を書かなければ地の文）"] }
] }
{ "type": "message", "style": "bubble", "talk": [ … ] }
```

`who` は `public/data/characterdata.json` のキー。名前欄にはそのキャラの `name` が出る。
`lines` は行の配列。**1 つの `{}` が 1 回ぶんの表示**で、決定キーで次へ進む。

会話ウィンドウは**3 行の窓**（GS-146）。4 行目以降を書いても大丈夫で、**あふれたぶんは上へ巻き上がる**
（旧作と同じ。窓の大きさは変わらない）。**次の `{}` に進むと必ず空から**打ち直すので、
前の人の文字が残ることはない。長い行は折り返すので、折り返し 1 行も 1 行として数える。

`style` は見せ方（GS-23）。

| | どこに出るか | 何に使うか |
| --- | --- | --- |
| `window`（既定） | 画面の下の会話ウィンドウ | イベントの会話。立ち絵と一緒に |
| `bubble` | **喋っている人の頭の上**（顔アイコン付き） | フィールドの立ち話。NPC に話しかけたとき |

吹き出しは、主人公（`meina`）なら**プレイヤーの頭の上**、それ以外なら**話しかけた相手の頭の上**に出る。
アイコンは `characterdata.json` の `icon`（`assets/img/charIcon/<名前>.png`）。無ければ絵なしで出る。

### scroll —— 流れる文字

```json
{ "type": "scroll", "speed": 1800, "dim": 0.5, "lines": ["昔々（？）", "", "……"] }
```

画面を `dim`（0〜1）ぶん暗くして、`lines` を下から上へ流す。旧作のオープニングと同じ。
**決定キーかクリックで飛ばせる。** 空行は `""` で入れる。

`speed` は**1 行ぶんが流れる時間**（ミリ秒。既定 1800）。総時間ではない（GS-144）——
総時間で書くと、行数が少ない読み物ほど速く流れて読めなくなる。
**1 行が現れる間隔がそのまま読む時間**なので、長い文が並ぶなら 1800、
「シナリオ：俺」のような短い行が並ぶエンドロールなら 1200 くらい。16 行なら 1800 で約 61 秒。
遊ぶ人は設定の「流れる文字」で 0.5〜4 倍に変えられる（台帳の値に掛かる）。

### choice —— 選択肢

```json
{ "type": "choice",
  "prompt": { "who": "grandpa", "lines": ["……で、今日は出かけるのかね？"] },
  "choices": ["行ってくる", "やめておく"],
  "cancel": 1,
  "branches": [ [ …選んだときの命令… ], [ …2 つ目… ] ] }
```

`prompt` は選択肢の前に出す会話（省略可）。`cancel` はキャンセルしたときに選ばれる番号。
`branches` は `choices` と同じ並び。枝の中にも同じ命令が書ける（入れ子にできる）。

### move / turn —— 歩く・向く

```json
{ "type": "move", "target": "npc:chicken_walk", "to": { "x": 2, "y": 10, "z": 2 } }
{ "type": "move", "target": "player", "to": { "x": 12, "y": 0, "z": 8 }, "first": "upDown" }
{ "type": "turn", "target": "this", "to": "down" }
```

| 欄 | 中身 |
| --- | --- |
| `target` | `player` / `this`（話しかけた相手）/ `npc:<名前>` |
| `to` | **行き先のマス**（整数）。そこまで歩く。`y` は見ない（高さは床が決める）。`place` と同じく軸に **`"player"`** と書ける（GS-154）|
| `first` | 曲がる順。`leftRight`（既定）は**横から**／`upDown` は**縦から** |
| `speed` | 6 以上で走る。省略は歩き |
| `slide` | `true` で**向きも足も動かさずに運ぶ**（GS-155）。殴られて後ろへ飛ぶ・氷で滑る |
| `wait` | `false` にすると歩き終わるのを待たずに次の命令へ進む |
| `to` | `turn` の向き |

**歩かせ方は行き先だけ**（GS-139）。1 マスずつの道順は無くなりました。

**飛ばされる絵は `slide`**（イベントエディタの「滑らせる」）。先に `turn` で向きを決めてから
`slide` で運ぶと、**その向きのまま**下がります。速さは上げないこと——走りにすると、
画面が隠れてコマ落ちしたときに着地が 1 マスずれます。

```json
{ "type": "turn", "target": "player", "to": "up" },
{ "type": "move", "target": "player", "to": { "x": "player", "y": 0, "z": 8 }, "first": "upDown", "slide": true }
```

**横の軸を `"player"` にすると「その軸は動かさない」**＝**真後ろ**へ飛びます。数で書くと、
踏んだマスによっては斜めに滑ります（0103 の出会いで実際そうなっていました）。

- 道順は**いまの立ち位置から**組みます。片方の向きを詰めてから曲がる **L 字** です
- `first` で**どちらから先に行くか**を選びます。同じ行き先でも通る道が変わるので、
  行き止まりや障害物を避けたいときに使い分けます

```
    P . . .          P . . .
    . . . .          . . . .
    . . . G          . . . G

    leftRight …… 右へ 3 → 下へ 2
    upDown   …… 下へ 2 → 右へ 3
```

- **壁は避けません。** 進めないマスは 1 歩あたり 0.3 秒で諦めて次へ行くので、
  塞がっていてもイベントは止まりませんが、**着きません**
- 道順を組むのがゲーム側なのは、歩く向きが**カメラの方位で回る**からです。
  「x が 3 増える」がどの向きの何歩になるかはマップのカメラ次第で、イベントからは決められません
- 遠すぎる行き先は 64 歩で打ち切り、コンソールに出します（座標の打ち間違い避け）
- **行き先は位置そのもの**です。「その場から 1 歩下がる」のような**相対の動き**は書けません——
  起動枠が広いイベントでは、立っていた場所によって寄る向きが変わります

**壁で進めないときは 0.3 秒で諦めて次へ進む。** イベントがそこで止まらないように。

### place —— その場に置き直す（GS-137）

```json
{ "type": "place", "target": "npc:chicken_walk", "at": { "x": -6, "y": 0, "z": 1 }, "face": "down" }
{ "type": "place", "target": "npc:lamy_32_40", "at": { "x": "player", "y": "player", "z": 7 }, "face": "down" }
```

| 欄 | 中身 |
| --- | --- |
| `target` | `this`（話しかけた相手）/ `npc:<名前>`。**`player` は受けない** |
| `at` | マップのマス（整数）。**そのマスの真ん中**に立つ。軸に **`"player"`** と書くと**主人公と同じ座標**（GS-154）|
| `face` | 置いたあとの向き。省略すると今の向きのまま |

**`"player"` は軸ごとに混ぜられます。** 上の 2 つ目は「横（x）と高さ（y）はプレイヤーに合わせ、
奥行き（z）は 7」。旧作の `setPosition(player.x, 902)` がこの書き方です。
イベントエディタでは各軸の**「プレイヤー位置」**にチェックを入れます。



**歩かず一瞬で移ります。** 使いどころは「画面の外から歩いて来る」——
出番の前に道の奥へ置き、そこから `move` で歩かせると、いつ来たのか分からないまま現れます。

- **マップに置いた場所は書き換えません。** 入り直せばその人は元の場所に戻ります
- 歩いている・うろついている途中なら打ち切ります。**うろつきの起点も移す**ので、
  置いたそばから元の場所へ帰ろうとはしません（GS-48）
- `player` を指すと何もせず印が出ます。プレイヤーの立ち位置を飛ばすのは `transfer` の仕事です

### portrait —— キャライラスト

```json
{ "type": "portrait", "slot": "left", "who": "meina", "face": "normal" }
{ "type": "portrait", "slot": "center", "image": "メイナOP画像" }
{ "type": "portrait", "slot": "left", "hide": true }
```

**`image` はフリーイラスト**（GS-142）。`characterdata.json` を引かず、
`assets/img/CharaStand` の絵を**名前で直に**出す（拡張子は書かない）。
人に結び付かない一枚絵——回想・看板・ロゴなど——のためのもので、
**書いてあれば `who` より優先**する。表情は関係ない（台帳を引かないので）。
イベントエディタでは「フリーイラスト」の欄に**手で打つ**（EE-12）。
置き場に無い名前を打つと欄の横で知らせるが、**止めはしない**——絵を後から足す順序もあるので。

`slot` は `left` / `right` / `center`。同じ場所は 1 枚だけで、置き直すと差し替わる。
**`who` を空にする（または `"hide": true`）とその場所を空ける。**
イベントエディタでは「誰」を（なし）にする——`hide` の欄は置いていない（EE-11）。
**出入りは画面の外から／外へ**（来た側。0.28 秒）。`"instant": true` を書くと動かずにその場で出入りするが、
エディタからは書けない（使っている所が無かった）。
`face` は `characterdata.json` のキー（`talk` / `normal` / `smile` / `unger`）。
**省くと `talk`（会話用の絵）→ `normal`（立ち絵）の順に落ちる**——
メイナは会話用にバストアップ（`EventTalkImage001`）を持っているので、書かなければそちらが出る。

イベントエディタでは**選ぶだけ**で、出るのは**その人が絵を持っている表情**だけ（EE-10）。
新しく足した「立ち絵」は **`normal` が入った状態**で始まり、**空欄は選べない**——
画面で見ている表情と、書かれている表情を食い違わせないため。
上の「落ちる順」は、手で書いた古い台帳を読むための道として残っている。
**絵の割り当ては台帳エディタの「イラスト」**（5931）で決める。
**イベントが終わると自動で片付く**ので、消し忘れても次のイベントには残らない。

**`id` はこのイベントの中だけの名前**（GS-143）。付けなければ `slot` が名前になるので、
今までどおり「左の絵」「右の絵」として扱える。付ければ**同じ場所に何枚でも重ねられ**、
下の `imageFx` で 1 枚ずつ動かせる。`from` は入ってくる向き（`left` / `right` / `top` / `bottom` / `none`）。
省くと置いた側から滑り込む。

`flip` を `true` にすると**左右反転**（GS-146）。右に置いた絵を左向きにしたいときに使う。
立ち位置は動かない。途中で向きを変えたいときは**同じ名前で置き直す**。

### imageFx —— 出ているイラストを動かす（GS-143）

```json
{ "type": "imageFx", "id": "ラミィ", "kind": "out", "to": "left", "ms": 300 }
{ "type": "imageFx", "id": "メイナ", "kind": "shake", "power": 8, "ms": 300 }
{ "type": "imageFx", "id": "ラミィ", "kind": "fade", "opacity": 0.4 }
{ "type": "imageFx", "id": "じいちゃん", "kind": "zoom", "scale": 1.6, "ms": 400 }
```

| 欄 | 中身 |
| --- | --- |
| `id` | どの絵か。`portrait` で付けた名前（付けていなければ `left` / `right` / `center`）|
| `kind` | `out`（外へ流して消す）/ `shake`（揺らす）/ `fade`（濃さを変える）/ `zoom`（大きさを変える）|
| `to` | `out` の流す先。省くと**入ってきた側へ帰る** |
| `power` | `shake` の揺れ幅（画素）。省くと 8。終われば元の位置へ戻る |
| `opacity` | `fade` の行き先の濃さ（0〜1）。0 で見えなくなる（**絵は残る**）|
| `scale` | `zoom` の倍率。1 がふつう、2 で 2 倍（0.1〜8）。**軸は足元**なので立ち位置は動かない |
| `ms` | かける時間。省くと 280 |
| `wait` | `false` にすると動き終わるのを待たない |

- **出ていない名前を指すと何もしない**（コンソールに印）。黙って通すと「効かない」理由が分からない
- `out` は**画面の外へ出切ってから**消すので、途中で切れて見えることがない
- `fade` と `zoom` は**かけたままになる**。元に戻すなら戻す値でもう一度かける（`scale: 1`）
- **大きさを変えられるのは効果だけ**（GS-145）。画面側は**大きすぎる絵を縮めるだけ**で、
  小さい絵を引き伸ばさない（絵ごとの大小は元の絵のまま）。大きく見せたいときに `zoom` を使う

### fade / wait —— 暗転・待つ

```json
{ "type": "fade", "to": "out", "ms": 400 }
{ "type": "wait", "ms": 500 }
```

### transfer —— マップ移動

```json
{ "type": "transfer", "map": "0102", "at": { "x": 6, "y": 10, "z": -2 }, "face": "down" }
{ "type": "transfer", "map": "0102", "at": null }
```

`map` は台帳（`public/data/maps.json`）の番号か、ファイル名。
`at` は**マス（整数）**で、そのマスの中央に立つ。`null` なら行き先の `default` へ。

### setSwitch / setSelfSwitch / setVariable / if —— 覚える・分ける

```json
{ "type": "setSwitch", "key": "EVENT010101", "value": true }
{ "type": "setSelfSwitch", "key": "A", "value": true }
{ "type": "setVariable", "key": "所持金", "value": 100, "op": "add" }
{ "type": "if", "when": { "switch": "EVENT010101" }, "then": [ … ], "else": [ … ] }
{ "type": "if", "when": { "switch": "EVENT010401", "is": false }, "then": [ …あの話が済んだら… ] }
{ "type": "if", "when": { "self": "A" }, "then": [ … ] }
{ "type": "if", "when": { "variable": "所持金", "op": ">=", "value": 100 }, "then": [ … ] }
{ "type": "if", "when": { "item": "やくそう", "count": 2 }, "then": [ … ] }
```

`op` は `set`（既定）/ `add` / `sub`。比較は `==` `!=` `>=` `<=` `>` `<`。

フラグの条件は `when` と同じ向き（GS-147）。**`is` を省くと「まだ動ける（true）とき」**で、
「**あの話が済んだら**」は `is: false` と書く（例: ラミィが仲間になった＝`EVENT010401` が済んだ）。

**セルフフラグ**（`setSelfSwitch` / `when.self`）は**そのイベントだけの覚え**（GS-27）。
「この宝箱は開けた」をマップ通しのフラグにすると、置くたびに名前を考えることになる。
中では `<マップ>/<イベント>/<名前>` として覚える。名前は `A` `B` … でよい。

### playBgm / playSe / stopBgm —— 音

```json
{ "type": "playBgm", "key": "field", "volume": 0.5 }
{ "type": "playSe", "key": "decide" }
{ "type": "stopBgm", "fade": 800 }
```

`key` は `public/data/sounds.json` の名前。**音を増やすのはファイルを置いて台帳に 1 行**（GS-21）。
マップごとの曲と環境音は `public/data/maps.json` に書く（イベントに書かなくてよい）。

### pose —— 姿を変える（GS-47）

```json
{ "type": "pose", "target": "npc:宝箱_家1", "name": "開いた" }
{ "type": "pose", "target": "npc:宝箱_家1", "name": null }
```

**絵のコマだけを止めて差し替える。** 宝箱の開閉のように「見た目が変わって、そのままでいる」もの用。
`name` は台帳（`data/actors.json`）の `poses` のキー。`null` を渡すと指名を外し、歩きと向きの絵に戻る。

```json
"chest": {
  "sheet": "assets/spritesheet/chest.png",
  "cols": 2, "rows": 1, "framePx": [32, 32],
  "poses": { "閉じている": 0, "開いた": 1 }
}
```

- 番号ではなく**名前**で指すので、シートを描き直してコマの順が変わってもイベントを直さなくてよい
- 指名している間は**歩いても向きを変えても絵は変わらない**
- 台帳に無い名前なら何もせず、コンソールに出る

**宝箱はイベント 1 本**（GS-133 / GS-134）。**中身も見た目も台帳**（`chests.json`）が持つので、
イベントに書くのは「開けたら何が起きるか」だけになる。

| 書く場所 | 何を |
| --- | --- |
| マップのオブジェクト | `SPRITE` レイヤーに置く（物。うろつかず、向かず、**吹き出しも出ない**。GS-136）|
|  | `Id` = `宝箱_家1`（名前。**開けた覚えも台帳の引き当ても、ここに付く**）|
|  | `Event` = `宝箱`（どのイベントで開けるか。**何個の物で同じ id を指してもよい**）|
| 宝箱の台帳 | `chests.json` に 1 行（中身と、閉／開のコマ。GS-135。編集はイベントエディタの「宝箱」）|
| イベント | 下の 1 本だけ。**どの宝箱でもこれ 1 本**（GS-134）|

```json
{ "id": "宝箱", "trigger": "action", "kind": "object",
  "commands": [
    { "type": "if", "when": { "self": "開けた" },
      "then": [{ "type": "message", "talk": [{ "lines": ["からっぽだ。"] }] }],
      "else": [
        { "type": "playSe", "key": "chest" },
        { "type": "getItem" },
        { "type": "setSelfSwitch", "key": "開けた", "value": true },
        { "type": "message", "talk": [{ "lines": ["{アイテム} を 手に入れた！"] }] }
      ] }
  ] }
```

- **`setSelfSwitch` は `message` より先**（GS-136）。見た目はフラグから導くので、
  **この順番がそのまま「押したら開いて、それから読む」になる**。後ろに書くと、
  読み終わるまで閉じたままに見える。逆に書くとテストが落ちる（`tests/eventBook.test.ts`）
- **`pose` の命令は要らない。** フラグが入ったその場で絵が変わり、マップを読み直しても開いたまま
- **見た目はセーブに入れない。** 記録が持つのはフラグだけで、そこから毎回導く（GS-47 と同じ考え）
- **覚えは物ごと**（`Id`）。だから同じイベントを何個の宝箱で使っても混ざらない
- 開ける前と後は `if` で分ける（1 つの物に結べるイベントは 1 本）
- 中身は `getItem` の `id` を空にすると**台帳の中身**（`item` か `random` の抽選）、
  `count` を省くと台帳の `num`。文の中の `{アイテム}` はその名前に変わる

`id` を書けばそちらが勝つ。`Item` も `id` も無ければ何もせず、コンソールに出る。
### block —— ブロックの絵を差し替える（GS-53）

```json
{ "type": "block", "at": { "x": 5, "y": 0, "z": -3 }, "chip": 41 }
{ "type": "block", "at": { "x": 5, "y": 0, "z": -3 }, "faces": { "top": 41, "front": 42 } }
{ "type": "block", "at": { "x": 5, "y": 0, "z": -3 }, "chip": 41, "layer": "宝箱" }
```

**マップに置いたブロック 1 マスの絵を差し替える。** `pose` がスプライト（板 1 枚）の話なのに対し、
こちらは**ブロックそのもの**——チップを貼り付けて置いた宝箱や橋のような、
地形として置いてある物の見た目を変える。

- `chip` は**全部の面**をその番号に。`faces` は面ごと（`top` / `bottom` / `front` / `back` / `left` / `right`）
- 両方書いたら `faces` が勝つ（`chip` で下地を敷いて、上の面だけ差し替える書き方ができる）
- `layer` を書くとそのレイヤーのマスだけ。省くと**一番上のレイヤー**
- そのマスにブロックが無ければ何もせず、コンソールに出る

**変えられるのはチップ番号だけ。** 形（ブロックの高さや切り欠き）も絵柄（タイルセット）も変わらない。
だから**当たりも影もそのまま**で、置き換えても事故が起きない代わりに、
「開けたら通れるようになる宝箱」のような当たりが変わる物はこれだけでは作れない。

> なぜチップ番号だけか：形が変われば当たりも影も組み直しになり、その 1 マスのために
> マップ全体を作り直すことになる。番号の書き換えは、滝や水面のアニメーションが
> 毎フレームやっているのと同じ道を通るので、ただの数値の上書きで済む。

**マップに戻ってきたときも開いたまま**にするのは `pose` と同じ——見た目はセーブに入れず、
フラグ 1 つから `parallel` で毎回導く（GS-43）。

```json
{ "id": "宝箱_森", "trigger": "action",
  "when": [{ "self": "A", "is": false }],
  "commands": [
    { "type": "playSe", "key": "chest" },
    { "type": "getItem", "id": "やくそう" },
    { "type": "block", "at": { "x": 5, "y": 0, "z": -3 }, "faces": { "top": 41, "front": 42 } },
    { "type": "setSelfSwitch", "key": "A", "value": true },
    { "type": "setSwitch", "key": "宝箱_森_開けた", "value": true }
  ] }

{ "id": "宝箱_森_見た目", "trigger": "parallel",
  "when": [{ "switch": "宝箱_森_開けた" }],
  "commands": [{ "type": "block", "at": { "x": 5, "y": 0, "z": -3 }, "faces": { "top": 41, "front": 42 } }] }
```

### getItem / loseItem —— 持ち物（GS-46）

```json
{ "type": "getItem", "id": "やくそう", "count": 3 }
{ "type": "loseItem", "id": "やくそう" }
```

`id` は `public/data/items.json` のキー。`count` は省略で 1。
**減らすほうは別の命令**にしてある——負の数で渡す形にすると、書き間違いが静かに増えるので。

```json
{
  "items": {
    "やくそう": { "name": "やくそう", "text": "すこし元気になる" }
  }
}
```

- 台帳が持つのは**名前と説明だけ**。**持っている数はセーブ**が持つ（同じ物を 2 か所に置かない）
- 台帳に無い id でも渡せる（コンソールに出る）。台帳から消しただけで持ち物が飛ぶと、記録が読めなくなるため
- **0 個になったら消える**。「0 個持っている」は残さない
- Esc の画面に**持ち物の一覧**が出る（いまは見せるだけ。使う・捨てるはまだ無い）

持っているかで分けるのは `if`。

```json
{ "type": "if", "when": { "item": "やくそう", "count": 2 }, "then": [ … ] }
```

`count` 個**以上**持っているか。省略は 1。比べ方（`>=` など）は選べない——
「いくつ以上」以外はまず要らないし、選べると書くほうが迷う。
### shot —— カメラ演出（GS-73 / GS-75）

**GS-92（2026-09-12）**: 共通台帳から `{"type":"shot","id":"impact"}` で呼べます。演出は独立した Camera Editor で作成します。`id` がある場合は台帳を優先し、`wait:false` と `release:true` は従来どおり使用できます。カメラ演出はイベント専用です（戦闘のカメラはゲームのコードが持つ。GS-105）。

**イベントエディタ（EE-3。2026-09-18）**: `id` のある `shot` は「カメラ演出」、`id` の無い `shot` は「画面効果」という別の命令として表示します。JSON の形は同じです。

```json
{ "type": "shot", "kind": "flash" }
{ "type": "shot", "kind": "shake", "ms": 700, "power": 0.5, "wait": false }
{ "type": "shot", "kind": "veil", "color": "000000", "hold": true }
{ "type": "shot", "release": true }
```

光る（`flash`）・揺れる（`shake`）・寄る（`zoom`）・暗くする（`veil`）。
**値はここに書く**ので、どのマップでも同じように使える（マップには持たせない）。

| 欄 | |
| --- | --- |
| `kind` | 省略すると `flash` |
| `ms` | 長さ。省略で 320 / 480 / 600 / 500（種類ごと） |
| `power` | `flash`・`veil` は濃さ 0〜1、`shake` は揺れ幅（マス）、`zoom` は倍率 |
| `color` | `flash` と `veil` だけが使う（6 桁 hex） |
| `hold` | `zoom`・`veil` を戻さず残す。戻すのは `release` |
| `wait` | **既定は待つ**。`false` で待たずに次の命令へ |

エディタの**カメラ編集 → カメラ演出**で、用意されている演出を既定の値で試せる（作る欄は無い）。

### party —— 仲間の出入り（GS-70）

```json
{ "type": "party", "op": "join", "who": "lamy" }
{ "type": "party", "op": "leave", "who": "lamy" }
```

`who` は `data/party.json` の `members` に居る人。**台帳に居ない人は入らない**
（数値の無い仲間は、戦闘に出た瞬間に無敵か即死になる）。

- **最後の 1 人は外せない**——誰も居ない隊列は次の戦いで即座に負ける
- 外しても**育ち具合は残る**ので、入り直すとそのまま戻る
- 隊列が 2 人以上になると、メニューの左の柱に全員の HP/MP が並び、
  そうび・スキル・ステータスに「誰を見るか」の列が出る

### gold —— お金（GS-65）

```json
{ "type": "gold", "op": "add", "value": 50 }
{ "type": "gold", "op": "sub", "value": 10 }
```

`op` を省くと足す。**0 より下へは行かない**（借金の考えを持たない）。
いくら持っているかで分けるのは `if`。

```json
{ "type": "if", "when": { "gold": 10 }, "then": [ … ], "else": [ … ] }
```

`gold` 円**以上**持っているか。宿はこの 3 つで書ける——
`if` で持ち金を見て、`gold` で払って、`heal` で回復。

### shop —— 店（GS-66）

```json
{ "type": "shop", "items": ["やくそう", "ばんそうこう"], "sell": true }
```

閉じるまで次の命令へ進まない。**値段は台帳**（`data/items.json` の `price`）が持つ——
店ごとに値段を変えられるようにすると、同じ薬が村ごとに違う値段になり、
書く人が全部を覚えていることになる。店が決めるのは**何を並べるか**だけ。

- 売値は**買値の半分**（切り捨て）。`price` の無い物（鍵や手紙）は並ばないし売れない
- `sell` を false にすると「かう」だけの店になる
- お金が足りない物は**消さずに押せなくする**（何が置いてあるかは見せる）

持ち物の台帳（`data/items.json`）は 3 つの顔を持つ。

| 書くもの | それでできること |
| --- | --- |
| `use` | 使える（GS-64）。`where` は field / battle / both |
| `price` | 店で売り買いできる（GS-66）。売値は半分 |
| `equip` | 身に着けられる（GS-67）。`slot` は weapon / armor |

どれも書かなければ「持っているだけの物」（鍵や手紙）。

### heal —— 回復（GS-64）

```json
{ "type": "heal", "hp": "full", "mp": "full", "cure": "all" }
{ "type": "heal", "hp": 30, "who": "meina" }
{ "type": "heal", "cure": ["poison"] }
```

宿・泉・話の区切りで使う。`who` を書かなければ**隊列ぜんぶ**。
`"full"` は満タンまで、数はそのぶんだけ（満タンは超えない）。

`cure` は消す状態異常（GS-71）。`"all"` ならかかっている物ぜんぶ——**宿はこれ**。

**持ち物の「使う」と同じ式**（`battle/heal.ts`）を通るので、
宿とやくそうで効き方が食い違わない。

### battle —— 戦う（GS-60）

```json
{
  "type": "battle",
  "enemies": ["enemy02", "enemy02"],
  "formation": "standard",
  "win": [ { "type": "message", "talk": [ { "lines": ["おいはらった！"] } ] } ],
  "escape": [ { "type": "message", "talk": [ { "lines": ["…にげきった。"] } ] } ],
  "lose": [ { "type": "transfer", "map": "0101", "at": null } ]
}
```

**決着が付くまで次の命令へ進まない。** `enemies` は `public/data/enemies.json` のキーで、
**同じ id を 2 つ書けば 2 体出る**（2 体目からは名前に「B」が付く）。

`formation` はこのイベント戦闘で使う3D舞台の隊形ID（省略可能）。戦闘中のカメラ演出はイベントでは指定しない——戦闘演出エディタの割り当て（`battlePresentation.json`）が決める（GS-98。旧 `camera` は廃止）。`formation` を省くとマップの `battleStage.formations` 候補からランダム選択し、候補も無ければ `battleFormations.json` の `default` を使う。

- 枝は**書いたものだけ**動く。3 つとも省ける
- **`lose` を書かなければ、負け＝ゲームオーバー**（ゆっくり暗くなってタイトルへ）。
  記録は書き換えないので、最後にセーブしたところから遊び直せる
- `lose` を書いたときは「負けても話が続く」戦い（負けイベント）になる
- 出会い頭の戦闘（マップの台帳に書く `encounter`）は**いつも負け＝ゲームオーバー**——
  そこには続きを書いた人が居ない

- 勝つと**経験とお金**が入る（敵の台帳の `exp` / `gold`）。レベルが上がればその場で全快する（GS-63）
- `lose` を書いた戦いで負けたときは、倒れた仲間を **HP 1** で起こしてから枝へ進む

数値と技は `data/enemies.json` / `data/skills.json` / `data/party.json`、
状態異常は `data/ailments.json`（note/00 §4.19）。**状態異常は戦いのあいだだけ**続く。

### callCommon —— 共通イベントを呼ぶ（GS-44）

```json
{ "type": "callCommon", "id": "宝箱をあける" }
```

**何度も使う命令の並びに名前を付けて、名前で呼ぶ。** 置くたびに同じ命令を書き写すと、
直すときに全部を探して回ることになる。

置き場所は `public/data/commonEvents.json`。ほかの台帳（`maps` / `actors` / `sounds`）と同じ形で、
**増やすのはファイルに 1 つ足すだけ**。TS は触らない。

```json
{
  "commons": {
    "宝箱をあける": {
      "name": "宝箱をあける",
      "commands": [
        { "type": "playSe", "key": "chest" },
        { "type": "setSelfSwitch", "key": "A", "value": true }
      ]
    }
  }
}
```

- **どのマップからでも呼べる**（マップのイベントとは別物）
- 中では**呼んだ側のイベントの覚え**をそのまま使う。上のように `setSelfSwitch` を書けば、
  「その宝箱」の覚えになる——共通イベントの覚えにはならない
- 名前が台帳に無ければ**何もせずに次へ進み**、ブラウザのコンソールに出る
  （`[event] 共通イベントが見つかりません: …`）。イベントがそこで止まらないため
- イベントエディタでは**一覧から選べる**。台帳が空のうちは手で書ける

### script —— TS の関数を呼ぶ（GS-45）

```json
{ "type": "script", "id": "オープニングの演出", "args": { "ms": 3000 } }
```

**JSON にコードは書かない**（GS-06）。書けるのは `src/game/scriptBook.ts` に**登録した名前**だけ。
命令を 1 つ足すほどではない**一度きりの演出**を、型を触らずに置くための逃げ道。

```ts
// src/game/scriptBook.ts
export const SCRIPTS: Record<string, ScriptFn> = {
  オープニングの演出: async (args, ctx) => {
    await ctx.fade('out', 400);
    await ctx.wait(typeof args.ms === 'number' ? args.ms : 1000);
  },
};
```

- `ctx` は**イベントから見える世界そのもの**（会話・歩き・フラグ…）。命令でできることはここでもできる
- `args` は JSON に書いた値がそのまま入る
- 名前が無ければ**何もせず次へ進み**、コンソールに出る（`[event] script が登録されていません: …`）
- イベントエディタでは**一覧から選べる**（登録が空のうちは手で書ける）

**ここへ書かないほうがよいもの**

| | 正しい置き場所 |
| --- | --- |
| 命令の並びで書けるもの | 共通イベント（`data/commonEvents.json`。GS-44） |
| どのイベントでも使うもの | 命令を 1 つ足す（`types.ts` と `interpreter.ts`） |

`scriptBook.ts` が太ってきたら、それは**命令にすべきものが混ざっている**合図。

## 3. 名前の決まり

| 何の名前 | どこが持つ | 例 |
| --- | --- | --- |
| キャラ（会話・立ち絵・アイコン） | `public/data/characterdata.json` | `meina` / `grandpa` / `mob` |
| キャラ（歩く絵） | `public/data/actors.json` | `meina` / `grandpa` / `enemy02` |
| NPC（イベントから指す） | マップの `NpcId`、無ければ姿のキー | `chicken_walk` |
| 姿（`pose` で指す） | `public/data/actors.json` の `poses` | `開いた` |
| 音 | `public/data/sounds.json` | `field` / `waterfall` / `decide` |
| マップ | `public/data/maps.json` | `0101` / `0102` |
| フラグ・変数 | イベントが書いた時点で生まれる | `EVENT010101` / `EVENT010201` |
| セルフフラグ | 同上。**そのイベントの中だけ** | `A` / `B` |

**フラグと変数は前もって作らない。** 使った名前がそのまま入れ物になる。

**「この話は済んだ」を覚えるフラグは、そのイベントの id と同じ名前にする**（GS-140）。

### フラグの向き（GS-147）

**`true`＝まだ動ける（実行可能）／`false`＝もう動かない（済み）。書いていなければ `true`。**
旧作の `savedata.json` の `EventFlag` と同じ向きで、あちらも「書いていない＝動ける」でした。

1 回きりのイベントは、こう書きます。

```json
"when": [{ "switch": "EVENT010201", "is": true }],
"commands": [ … , { "type": "setSwitch", "key": "EVENT010201", "value": false } ]
```

- 初回は**誰も書いていない**ので `true`＝動く
- 終わりに自分を `false`＝以後は動かない
- 「あちらが済んでから」は **相手が `false`** で書く（`{ "switch": "EVENT010301", "is": false }`）
- **`setSwitch` を `true` で終わらせない。** 何度でも動くイベントになる（テストが落ちます）

マップの `ShowIf` も同じ向き。**`ShowIf: EVENT010201`＝そのイベントがまだ動けるあいだだけ出す**
ので、話が終わった瞬間に消えます（0102 の鶏・0105 のボス）。

**セルフフラグだけは逆向き**（`setSelfSwitch` / `when.self`）。あちらは「この宝箱は開けた」という
**済んだ覚え**で、未設定＝`false`、開けたら `true` です。

### セルフフラグの使いどころ（GS-27 / GS-134）

**覚えの行き先は「物ごと」**。マップの `Id` が付いていればその物、無ければイベント自身です
（`<マップ>/@<物の Id>/<名前>` または `<マップ>/<イベント id>/<名前>`）。
だから**同じイベントを何個の物に付けても、覚えは混ざりません**。ここが通しのフラグとの分かれ目です。

**1. 宝箱（いま動いているもの）** —— 3 つの宝箱に同じ `宝箱` イベントを付けても、開けた覚えは別々。

```json
{ "type": "if", "when": { "self": "開けた" },
  "then": [ { "type": "message", "talk": [{ "lines": ["からっぽだ。"] }] } ],
  "else": [
    { "type": "playSe", "key": "chest" },
    { "type": "getItem" },
    { "type": "setSelfSwitch", "key": "開けた", "value": true },
    { "type": "message", "talk": [{ "lines": ["{アイテム} を 手に入れた！"] }] } ] }
```

**2. 初めてだけ長く喋る NPC** —— 2 回目からは短い挨拶に変える。

```json
{ "id": "talk_grandpa", "kind": "talk", "trigger": "action", "commands": [
  { "type": "if", "when": { "self": "挨拶済み" },
    "then": [ { "type": "message", "talk": [{ "who": "grandpa", "lines": ["気を付けてな。"] }] } ],
    "else": [
      { "type": "message", "talk": [{ "who": "grandpa", "lines": ["おお、大きくなったな。"] }] },
      { "type": "setSelfSwitch", "key": "挨拶済み", "value": true } ] } ] }
```

**3. 選んだ結果を覚える** —— 分岐の中で立てると「前に断った／受け取った」が次回に残る。

```json
{ "type": "choice", "choices": ["もらう", "いらない"], "branches": [
  [ { "type": "getItem" }, { "type": "setSelfSwitch", "key": "渡した", "value": true } ],
  [ { "type": "message", "talk": [{ "lines": ["……そうか。"] }] } ] ] }
```

**4. 見た目を覚えから変える** —— マップの物に `Pose: 開いた` と `PoseIf: self:開けた` を書くと、
イベントが `開けた` を立てたその場で絵が変わり、**マップを出入りしても開いたまま**（GS-133）。
`ShowIf` / `HideIf` にも `self:` と書けます。

#### 気をつけること

- **話しかけても無反応にしたくないなら `when` ではなく `if` を使う。**
  `"when": [{ "self": "済み", "is": false }]` と書くと、覚えが付いたあとは
  **イベントごと動かない**＝話しかけても何も出ません
- **物に `Id` を付ける。** 無いとイベント id が行き先になり、同じイベントを付けた物どうしで覚えを共有します
- 名前は `A` `B` でも日本語（`開けた`）でもよい。宝箱の `開けた` だけは決まった名前で、
  見た目のコマ（`closed` / `opened`）に直結しています
- **セーブに入ります。** マップを出入りしても残るのが通しのフラグと同じで、違うのは行き先だけです

```json
"when": [{ "switch": "EVENT010201", "is": false }],
"commands": [ … , { "type": "setSwitch", "key": "EVENT010201", "value": true } ]
```

- **名前を見ればどの話か分かる。** 「森_見送られた」では、どのイベントのことか探す羽目になった
- 条件に並べたフラグが**そのまま前の話の一覧**になる
  （`EVENT010401` の条件に `EVENT010302` と書いてあれば、館の見送りの後、と読める）
- イベント id は**マップの中だけで重ならない**決まりだが、フラグは**ゲーム全体で 1 つ**。
  つまり id を全マップで重ねないこと。重なると別々の話が同じ覚えを共有してしまう
  （`tests/eventBook.test.ts` が見張っている）
- 話の進み具合ではない覚え（`ゲーム_クリア` のような**状態**）は、今までどおり中身の名前で付ける
