# SampleGame テスト観点

## 目的

SampleGame の変更後に、物語の進行、マップ操作、戦闘、表示、入力、データ連携が壊れていないかを確認する。
自動テストで検査できるデータ整合性と、実機でしか分からない操作感・見た目を分けて扱う。

## 優先度

| 優先度 | 意味 |
| --- | --- |
| P0 | 起動不能、進行不能、保存破損など、公開を止める問題 |
| P1 | 主機能の誤動作、イベントや戦闘の重大な不整合 |
| P2 | 操作性や表示の問題。回避手段はある |
| P3 | 軽微な見た目、文章、演出上の問題 |

## 基本確認環境

- PCブラウザ: ChromeまたはEdgeの現行版
- 表示領域: ゲーム基準サイズの1280×720
- 入力: キーボード、仮想パッド、利用できる場合は物理ゲームパッド
- データ状態: はじめから、セーブデータあり、セーブデータなし
- 実行前検査:
  - `npm run typecheck`
  - `npm test`
  - `npm run check:assets`
  - `npm run build`

## 11. シナリオ回帰ルート

最低限、次の流れは変更のたびに通す。

1. タイトルから「はじめから」を選ぶ。
2. オープニングを最後まで進める。
3. 家の中で会話を終え、移動可能になる。
4. 家から外へ出て、移動・衝突・マップ切替を確認する。
5. 村または次の目的地まで進み、NPC会話と選択肢を確認する。
6. アイテムまたは宝箱を取得し、メニューの所持数を確認する。
7. ラミィとの出会いイベントを通し、登場位置、会話、戦闘、戦闘後会話を確認する。
8. セーブしてタイトルへ戻り、ロード後も同じ進行状態であることを確認する。

## 12. 変更内容別の重点回帰

| 変更箇所 | 最低限見る範囲 |
| --- | --- |
| マップJSON・衝突 | 初期位置、壁、出入口、NPC、イベント地点、戦闘舞台 |
| イベント台帳 | 発火条件、会話順、フラグ、NPC表示、戦闘後、再入場 |
| キャラクター・台帳 | 画像、区切り、名前、能力、編成、全参照先 |

| UI・CSS | 1280×720、長文、最大桁、会話・選択肢・パッドの重なり |
| 戦闘処理 | 開始、コマンド、対象、勝敗、演出、戦闘後復帰 |
| セーブ形式 | 新規保存、上書き、再起動後ロード、旧データ |
| アセット | `check:assets`、実画面、404、BGM切替、音量 |
